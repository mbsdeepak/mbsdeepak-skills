# /readme

Read the code first; every claim must be true. Structure:

1. **Title + one-line pitch** (what it is, key tech).
2. **Results**: the real numbers, GIFs, or sample outputs that exist in the repo. Don't invent any.
3. **How it works**: 3-6 bullets or a small diagram. Mention the interesting internals.
4. **Quickstart**: exact install + run commands that actually work.
5. **Project layout**: short tree, key files only.
6. **Roadmap**: a few next steps.

Keep it scannable. Edit the existing README in place and keep any accurate content.
